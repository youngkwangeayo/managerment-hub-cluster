2. 코드 리포지토리(Repository) 관리 방향

서비스별 리포지토리 독립 유지: 운영 환경의 독립성과 보안을 위해 현행대로 서비스별 리포지토리는 별도로 관리합니다.

K8s 설정(Helm Chart) 디렉토리 구조 개편:

네임스페이스별 관리를 용이하게 하기 위해 helm-charts/ 하위에 {Namespace} 단위를 추가합니다.

구조 예시:
helm-charts/{NS}/{service}

3. 개발자 로컬 환경 작업 가이드 (권장)
개발 클러스터 통합에 따라 로컬에서의 인프라 코드 관리 효율성을 위해 아래와 같은 디렉토리 구성을 권장합니다.

infra/ 디렉토리 하위에 각 서비스를 배치하면, 개발 통합 클러스터 작업 시 훨씬 직관적이고 편리한 작업이 가능합니다.

로컬 구성 예시:

Plaintext
infra/
├── cms/
└── aiagent/
(참고: 로컬 작업 구조는 동일하되, 실제 배포되는 개발 환경만 같은 클러스터를 공유하게 됩니다.)
